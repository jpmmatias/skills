Lesson 3 · Explain a streamed reply

Blocks and generation

One attention head is one step. A model stacks it into blocks, stacks the blocks, and then runs the whole stack once for every token it writes.

Why this matters for your mission: when you stream a reply or set temperature on an API call, you are watching and steering the loop in this lesson. By the end you can say what happens between two streamed tokens and predict what a temperature change will do.

residual streamThe running vector of each token. Every sub-layer reads it and adds its result back to it.
layer normRescales one vector to mean 0 and spread 1, then applies a learned scale and shift.
MLPA small two-layer network applied to each token's vector on its own.
logitsRaw scores, one per vocabulary token, before the softmax turns them into probabilities.

Inside one block

A decoder block has two sub-layers: the masked self-attention of lesson 2, then an MLP. The version below is GPT-2's, read straight from its released code: normalise, run the sub-layer, add the result back, twice513. Step through it.

Start: x, one 768-wide vector per token (lesson 1's embeddings, or the previous block's output).

Normalise each vector, then run masked self-attention on the normalised copies.

Add attention's output back onto x. The straight line is the residual connection: x itself passes through untouched.

Normalise again, then the MLP: widen each vector 4×, apply GELU, project back. Each token is processed on its own here.

Add the MLP's output back. The result has the same shape as x, so blocks stack: GPT-2 small has 12.

In GPT-2's code this is two lines, x = x + attn(ln_1(x)) and x = x + mlp(ln_2(x)); the MLP width is 4 × 768 = 3,072 with a GELU5. Because every sub-layer only adds to x, a token's vector is gradually edited as it rises through the stack rather than replaced.

Which version is this? This is the pre-LN order (normalise before the sub-layer), used by GPT-25 and, with RMSNorm in place of layer norm, by Hugging Face's Llama implementation9. The original 2017 Transformer used post-LN: LayerNorm(x + Sublayer(x)), and a ReLU feed-forward of 512 → 2,048 → 51278. A 2020 analysis reports that pre-LN can be trained without the learning-rate warm-up post-LN needs14.

Worked example: shapes through GPT-2 small

The prompt “The cat sat on the” is 5 tokens (lesson 1). Follow the shape of the data; every size is from GPT-2's code defaults and vocabulary52.

token ids                          5
+ embeddings (wte row + wpe row)   5 × 768
block 1 … block 12                 5 × 768     each: x + attn(ln_1(x)), x + mlp(ln_2(x))
final layer norm (ln_f)            5 × 768
× wteᵀ  (the token table again)    5 × 50,257  one score per vocabulary token, per position
keep the last row                  50,257      the logits for the next token

Only the last row is used to pick the next token: thanks to the causal mask, it is the only position that has seen the whole prompt5. GPT-2 reuses its token-embedding table to turn that vector into scores.

Your turn

Writing a reply, one token at a time

GPT-2's sampling loop does the same five things for every new token: take the last position's logits, divide them by the temperature, turn them into probabilities, draw one token, append it, and run again513. Press ▶ or use the chapter buttons; the probabilities and the reply are illustrative.

A real implementation does not recompute everything for the prompt on every step: GPT-2's code keeps the keys and values of earlier positions and only runs the new token through the blocks5. The result is the same; it is faster.

Temperature

Temperature T divides every logit before the softmax513. The ranking of tokens never changes; only how far apart their probabilities are.

Worked example: T = 2

Illustrative logits for the token after “The cat sat on the”: ␣mat 3.0, ␣floor 2.2, ␣sofa 1.8, ␣bed 1.5, ␣roof 0.5.

Now drag the temperature yourself. Below 1 the top token takes more of the probability; near 0 the choice becomes greedy (always the top token); above 1 the tail gets more chances.

Milestone challenge

Predict, then measure, a temperature change

Pick one prompt from your own work that has more than one reasonable short answer (a product name, a one-word label, a first word). Write down what you expect at temperature 0 and at a high temperature (for example 1.5, or the highest your API allows). Then call your API 10 times at each setting with a short length limit, and compare.

What to send back

Your prediction (written before the runs), the 20 outputs grouped by setting, the model and settings you used, and a short explanation of the difference in terms of logits, temperature and sampling.

Pass criteria

  1. The prediction is dated or placed before the results and names an expected number of distinct outputs at each setting.
  2. The 20 outputs are listed with the model name, the temperature and the length limit for each group, and the number of distinct outputs per group is counted.
  3. The explanation traces one output token through the loop: last-position logits, divided by temperature, softmax, one sampled token, appended.
  4. Any mismatch between prediction and result is named, with one possible cause (for example ties near the top, or a provider applying other sampling settings).

When you are done, send your work to your teacher in the terminal.
