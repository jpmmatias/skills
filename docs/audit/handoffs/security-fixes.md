# Handoff: security and reliability fixes (SR-01 … SR-13), plus runtime items from the skills review and course authors

Source findings: [reviews/security-reliability.md](../reviews/security-reliability.md). Not committed. `examples/**`, README, `docs/GUIDE.md`, templates and SECURITY.md were not touched: the example courses still carry **old copies of `assets/`** and need the orchestrator's re-sync.

Verification at the end of the pass: `node --test tests/*.test.mjs` → **239 pass, 0 fail** (183 before, +56 new). `node scripts/validate.mjs --strict` → **0 errors, 0 warnings, OK**. Starter templates + assets in a scratch workspace: every page loads in Chromium with no JS error, console error or failed request; the lesson renders 5 practice items and records an answer; `check.mjs` on that workspace: all pages clean, exit 0.

## How the before/after was measured

The before state is `git archive HEAD` of commit `685e07c`, the code the review was written on, unpacked in the scratchpad. The after state is the working tree. Each proof of concept runs against both through one harness (`ROOT=…`): scratchpad `poc/p01-sanitize.mjs`, `p02-run.sh` (+ `p02-loaders.mjs`, `vm/*.js`), `p02-latency.mjs`, `p03-lint.mjs`, `p03b-exec.mjs`, `p04-practice-path.mjs`, `p05-quota.mjs`, `p06-store.mjs`, `p08-10-13.mjs`, `p11-resolve.mjs`, `p-starter.mjs`. The browser was headless Chromium (Playwright 1.63, global install); Node 22.23.

New tests were run against the same pre-fix copy (the new test files copied into it). Every new test fails there, except four sanity checks named below. The repo was never left broken.

## Not fully fixed, and why

- **SR-02 is reduced, not removed.** The data files are still JavaScript that runs. Node's permission model does not cover the network, and on a Node without it the child can read files (it still has no environment, no host objects and a hard kill). The real fix is the ADR-004 follow-up: require `course.js` to be exactly `window.COURSE = <JSON>;` and parse it.
- **CSP directives `base-uri 'none'; form-action 'none'; object-src 'none'`** are not in the templates (I may not edit templates). Lint flags `<base>`, meta refresh, `<object>`/`<embed>` and `srcdoc` directly instead. Recommend adding these directives to all four templates; `cspProblems()` could then require them.
- **v1 courses:** CSP findings are warnings, not errors, to keep the pinned v1 baseline-fixture test green.
- **SECURITY.md** should say that CSP `'self'` on `file://` does not limit the path (SR-04). That is the orchestrator's file.
- **After a failed save the page stays in memory-only mode** for the rest of its life (as before). Imported events that did not fit stay in memory, and the notice tells the learner to export.
- **Write batching (SR-09)** was not done: callers read `persistent` synchronously.
- **`lessons[].requires`** is deprecated, not dropped (see the table above).
- **Examples:** `examples/*/assets/` still hold the old runtime. The orchestrator must re-sync them (`core.js`, `store.js`, `practice.js`, `progress.js`, `scene.js`, `diagram.js`, `viz.js`, `figures.css`). Their pages already carry the template CSP and lint clean with the new rules.
