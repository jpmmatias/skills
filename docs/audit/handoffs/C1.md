## Decisions

1. **The CSP is verified on `file://` in Chromium 1243 (Playwright 1.63)**, with `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'none'`.
   - **Allowed:** scripts and CSS from other folders (`../assets`), a dynamically injected `<script>` (which `review.html` needs), `<style>` and `style=""`, `data:` and local `file:` images, and Blob downloads (export).
   - **Blocked, as intended:** inline `<script>`, `fetch` and XHR (to `file:` and to `https:`), and remote images.
   - `'self'` therefore matches `file:` URLs in Chromium. Firefox and Safari are not verified.
   - **Consequence:** lessons must not contain inline scripts. Older lessons that do will break only if the meta tag is added to them; the templates are new pages.
2. **Item ids and versions.**
   - A positional legacy id includes the lesson number. The store keys by item only, so a bare `q1` would collide across lessons.
   - Answers migrated from v0 keep their v0 ids and still count toward L2 through the objective `l<n>`.
   - `itemVersion` is `store.itemVersion(item)`, computed over what the learner answers; editing only a `why` keeps the history.
3. **Option order** is `rng(item.id + store session)`: stable while the page is open and different after a reload. `Learncraft.seed` fixes it for screenshots and tests.
4. **Every graded attempt is recorded.** The store computes `attemptInSession` and `firstEver`. After feedback, a recall miss or a wrong pick marks later attempts `assisted: true`.
5. **Grading uses the UI's own normaliser, not `store.normalizeAnswer`.** It handles everything the store's version does, adds numeric tolerance, and keeps a leading `.` in numbers like `.5`, which the store's version strips.
6. **Practice files.**
   - `lessons[].practice` names the file.
   - In a v2 course a lesson without the field uses `lessons/NNNN.practice.js`.
   - `practice: null` means none. This avoids the console errors from a 404 for older lessons. **A and E: please document this and add it to the schema.**
7. **Typed recall answers** (the first 200 characters) are kept in the attempt's `note`. "Your record" tells the learner the export includes what they typed (orchestrator request 2). The `answer` alias was dropped; recall uses `accept` only (request 1).
8. **Level words follow `store.LEVEL_NAMES`:** Seen, Familiar, Understood, Applied, Retained, Transferred.
   - L4 comes from `milestoneMastered` in `course.js`, so a lesson can read "Applied · from your reviewed challenge" before its practice is done. This is consistent with ADR-005.
9. **"Next up" picks its order:** reviews due first (they are short and time-bound), then the challenge for an in-progress milestone whose lessons are all practised, then continue or start the next lesson. It shows at most one "Then:" line.
10. **The dashboard loads the practice files** (through the same loader as `review.html`) so that item counts and "Next up" are exact. That is why `index.html` loads `practice.js`.
11. **The deprecated `--act`, `--confirm` and `--triage` tokens** stay in `style.css`, marked deprecated. `figures.css` now has 0 uses, so they can be removed once C2 confirms that `examples/jev-confidence/` does not depend on them.

## Known limitations

- Chromium only. Firefox and Safari behaviour on `file://` (CSP `'self'`, `localStorage`, `document.write` in the legacy shim) is unverified.
- The legacy bootstrap uses `document.write`. It is parser-inserted and same-origin, works in Chromium, and is used only on pages without `core.js`.
- `practice.js` is 592 lines, about half of which are the en/pt string tables. `core.js` is 220 lines.
- The `.lc-why` level ladder states the store's thresholds as text. If D changes a threshold, the strings must change too.
- The review "early" message is inferred: a pass that leaves the box unchanged.
- Old v0 answers keep their v0 item ids, so a legacy lesson's counter starts at 0 for its `legacy:` ids. Levels still include them for L2.
- In `lesson.html` the optional figure scripts are commented out. C2's `diagram.js` needs `viz.js` loaded before it; the template order is viz → diagram → scene.
