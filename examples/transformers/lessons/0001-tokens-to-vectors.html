Lesson 1 · Read your prompt as the model does

From text to vectors

A model never sees your words. It sees a list of numbers, and then a list of vectors. This lesson follows a prompt from text to the vectors the first layer receives.

Why this matters for your mission: your mission says the APIs you call count your prompts and replies in tokens. This lesson shows what that unit is, why its count is not your word count, and what the model does with each token before any attention happens.

tokenA piece of text the model treats as one unit: a word, part of a word, a space plus a word, a punctuation mark.
vocabularyThe fixed list of every token a tokenizer can produce. Each entry has a number, its token id.
embeddingA vector of learned numbers that stands for one token id (or one position) inside the model.

Text becomes tokens

Here are real tokenizer outputs for a few short strings, from two of OpenAI's encodings: gpt2 (GPT-2's tokenizer) and the newer o200k_base34. A box is one token; ␣ marks a space.

Three things to notice. The space before a word belongs to the word: GPT-2's tokenizer first splits text with a pattern that keeps a leading space attached to the following letters5, so ␣strawberry and strawberry are different tokens. Numbers are cut into chunks, not digits. And the same text can cost a different number of tokens under a different tokenizer, so a count is only meaningful together with the tokenizer that produced it. As a rough scale, OpenAI's tokenizer docs say a token is about 4 bytes of text on average3.

How BPE learns its pieces

Both encodings above use byte pair encoding (BPE), brought to neural language models by Sennrich, Haddow and Birch in 20161. It learns its vocabulary from a training text: start from single symbols, count every pair of neighbours, merge the most frequent pair into a new symbol, and repeat2. Each merge adds one token to the vocabulary.

Worked example

A tiny training corpus: five words and how often each appears (the corpus from the Hugging Face docs2). Spaces between symbols show the current split.

Why does this step exist? Why count pairs weighted by how often each word appears, instead of once per word? Because the goal is to make the training text short in tokens: a pair inside a frequent word saves a token every time that word appears.

Each token id picks a row

After tokenizing, the model has a list of ids. It turns each id into a vector by looking up a row in a learned table, the token-embedding table. Nothing is computed from the spelling: id 3797 always fetches row 3797. In GPT-2's code the table is called wte, and its default width is 768 numbers per row5.

Where is the word order?

The next lesson's attention step compares vectors by their contents. Nothing in that comparison says which token came first. The original Transformer paper adds positional information for exactly this reason: the model “contains no recurrence and no convolution”, so order has to be put into the vectors78. Three designs you will meet:

  • Learned position table (GPT-2): a second table, wpe, with one learned row per position, 1,024 rows by default, added to the token row as in the figure above5.
  • Fixed sinusoids (the original 2017 Transformer): dimension pair i of position pos gets sin(pos / 100002i/d) and cos(pos / 100002i/d), added to the embedding. The authors report that learned positions gave nearly identical results78.
  • Rotary positions (RoPE; for example the Llama implementation in Hugging Face Transformers): nothing is added to the input; instead the queries and keys inside attention are rotated by an angle that depends on position910.

Milestone challenge

Tokenize your own prompts

Take three prompts you really send to an LLM API: one short, one long, and one with something unusual in it (code, numbers, a name, another language). Run them through a real tokenizer for the model family you use: tiktoken for OpenAI encodings, or the tokenizer your provider or open model publishes. Before one extra run, write down a prediction of how a small edit will change the count.

What to send back

A table (Markdown is fine) with, for each prompt: the word count, the token count, the tokens as the tokenizer printed them, and the tokenizer's name and version. Below it, your prediction and the result of the extra run, and one sentence on how the model you use encodes position, with the link where you found it.

Pass criteria

  1. The table lists 3 prompts of your own with word count, token count, printed tokens, and the tokenizer name and version.
  2. Two splits from your table are explained in one or two sentences each, naming the cause: a leading space, a rare word broken into frequent pieces, a number chunked, or a non-English word.
  3. A prediction written before the extra run (expected token count after one edit) sits next to the measured count, with one sentence on any difference.
  4. One sentence names the position method of the model you use (learned table, sinusoids, rotary, or other) and links the documentation or code you checked.

When you are done, send your work to your teacher in the terminal.
