React rendering cheat sheet

The vocabulary, the rules and the version notes of this course on one page, for React 19. Each rule names the lesson that teaches it and the source behind it.

Rules of thumb

  1. Rendered ≠ DOM changed. React changes only nodes whose output differs1. The catch: a render still costs the time it takes to call the component and its children.
  2. Same type + same position (+ same key) keeps state; a different type resets the whole subtree; a new key resets that component2. Position means the returned tree, not your if.
  3. A set call changes the value for the next render only6. Need the pending value? Pass an updater function7.
  4. One handler, one re-render. Updates are processed after the handler finishes7; separate clicks are separate.
  5. A render renders everything inside it unless a child is in memo with equal props11. Components above or beside the update are not called.
  6. Effects run after the commit; for clicks they may run before paint, so never rely on that order13. An Effect that sets state starts another render pass20.
  7. Doubled in development? Check Strict Mode first: component bodies render twice and Effects run setup → cleanup → setup, in development only14. Fix with a cleanup, not a ref guard12.
  8. memo needs stable props: a function or object created during render is new every time; use useCallback/useMemo only for memo props, Hook dependencies or measured slow work (about 1 ms or more)1617.

Reading the Profiler

  1. Install React Developer Tools; the browser extension adds the Components and Profiler panels23.
  2. Record one interaction; the Profiler groups work by commit. In the flame chart, components that did not render in the selected commit appear greyed out22 (described in a 2018 post; today’s panel differs in detail).
  3. For numbers in code, <Profiler onRender> reports actualDuration per update; profiling is off in production builds by default21.
