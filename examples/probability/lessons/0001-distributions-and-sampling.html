Distributions and sampling

Before you can say whether a dashboard number is surprising, you need to say which numbers randomness alone would produce, and how often.

Why this matters for your mission: every A/B test readout is one draw from a distribution; writing that distribution down and sampling from it is how you find out what “just noise” looks like for your metric.

How this page is grounded: the mathematics is standard and is derived here step by step. Every number on the page was recomputed by a script while writing it, and the simulation below checks the rest in front of you. The textbooks under Go deeper are where to read the full treatment; they could not be opened while this example was written, so they are marked unverified.

Four words first

random variable XA number produced by a random process: items in a cart, sign-ups among 5 visitors.
PMFProbability mass function: P(X = x) for every value x that X can take.
eventA set of values, such as “X ≤ 1”. Its probability is the sum of their PMF values.
sampleValues actually drawn from the distribution, by the world or by your simulation.

A PMF is a table that adds up to 1

A discrete random variable takes values you can list. Its PMF gives each value a probability, with two rules: every probability is between 0 and 1, and together they add up to exactly 1, because some value always happens. The probability of an event is the sum over the values in it.

P(X = x) ≥ 0  ·  Σx P(X = x) = 1  ·  P(X in A) = Σx in A P(X = x)

Worked example: heads in 3 fair flips

Let X be the number of heads in 3 flips of a fair coin. The 8 sequences HHH, HHT, …, TTT are equally likely, each 1/8, because the flips are independent and each side has probability 1/2. Count heads in each sequence and collect them:

  1. List every outcome and its probability (here all 1/8).
  2. Group the outcomes by the value of X and add their probabilities.
  3. Check the total is 1. If it is not, an outcome is missing or counted twice.
  4. Answer events by adding: P(X ≥ 2) = 3/8 + 1/8 = 1/2.

The same counting works when the trials are not 50/50. Say each of 5 visitors signs up independently with probability p (an illustrative model of a sign-up page). A particular sequence with k sign-ups has probability pk(1 − p)5 − k, and there are C(5, k) such sequences, the number of ways to choose which k visitors signed up:

P(X = k) = C(5, k) · pk · (1 − p)5 − k   (the binomial PMF)

Sampling: one uniform number per draw

A simulation needs to draw values with the PMF’s probabilities. Every language gives you a uniform random number u in [0, 1). Cut [0, 1) into consecutive slices, one per value, each as wide as that value’s probability. Then u lands in a value’s slice with exactly its probability, because for a uniform u the chance of landing in a stretch of [0, 1) equals the stretch’s length.

// pmf[x] = P(X = x) for x = 0, 1, 2, …; rng() returns a uniform number in [0, 1)
function sample(pmf, rng) {
  const u = rng();
  let total = 0;
  for (let x = 0; x < pmf.length; x++) {
    total += pmf[x];             // total = P(X ≤ x), the right edge of x's slice
    if (u < total) return x;     // u is inside x's slice
  }
  return pmf.length - 1;         // reached only if rounding left the total a hair below 1
}

Why does this line exist? Look at if (u < total). Why strictly less than, and not <=?

Show the reason

With <, value x owns exactly the slice [P(X ≤ x − 1), P(X ≤ x)), half-open like u itself, so the slices tile [0, 1) and a value with probability 0 owns an empty slice that the loop can never return. With <=, the slices become (left edge, right edge], which no longer matches u in [0, 1): a u of exactly 0, which rng() can return, would land on the first value even if its probability is 0, and a u exactly on an edge would go to the value on its left. Edge hits are rare (one chance in 232 per edge with this generator), but < makes the code match the picture exactly.

Use a seeded generator in simulations (in these lessons, Learncraft.rng(seed); in Python, random.Random(seed)). The same seed gives the same draws, so a surprising result can be rerun and checked.

Experiment: frequencies settle on the PMF

Below, a seeded generator draws X = successes in 5 trials again and again, using the sampler above. Bars show the share of draws at each value; the dashed line is the PMF. The lower chart follows the share of the most likely value draw by draw. This is a simulation: the numbers come from the seeded generator, and the same seed always gives the same draws.

Predict first: at 30 draws, how far (in percentage points) will the worst bar be from the dashed line? Then try it. Next, step n up to 10,000, and press New seed a few times at 30 draws and again at 10,000.

What you should see: at 30 draws the worst bar typically misses the PMF by around 10 percentage points, and the picture jumps when you change the seed; at 10,000 draws every bar almost always sits within about 1.5 points of its line, whatever p you choose. (Checked while writing this page: over 200 seeds at p = 0.30, the worst gap had a median of 10.1 points at 30 draws and never exceeded 1.4 points at 10,000; over 500 seeds at each p on the slider, 27 of 9,500 runs at 10,000 draws exceeded 1.5 points, the worst by 2.0.) The share of each value converges to its probability as the number of independent draws grows. That is the law of large numbers, stated and proved in both textbooks below13.

Notice how it converges. An early streak is not cancelled by later draws pulling the other way: the generator has no memory. It is swamped. An early surplus of 3 successes is a 10-point swing in the share after 30 draws and a 0.03-point blip after 10,000; later draws add their own noise, but it too shrinks as a share. The typical miss shrinks steadily but slowly as n grows; lesson 2 measures exactly how slowly.

Check yourself

Milestone challenge · Simulate a metric

Simulate one of your own metrics

Pick a small count from your own product: items per cart, failed logins per user per day, sign-ups per cohort of 5 visitors. Write its PMF from your own data (a week of logs is plenty), or as an honest guess if you have no data, labelled as a guess. Write a seeded sampler for it in your language, draw 100 values and then 10,000, and compare the observed shares with the PMF.

What to send back

The PMF table and where its numbers came from; the sampler code; a table of observed shares at n = 100 and n = 10,000 next to the PMF; the seed you used.

Pass criteria

  1. The PMF lists every value with a probability between 0 and 1, the probabilities add up to 1 (within 0.001), and the source of each number is stated.
  2. The sampler uses one uniform number per draw and a fixed seed; running it twice with the same seed prints identical samples.
  3. The table shows the observed share of every value at n = 100 and at n = 10,000, and the largest gap from the PMF at 10,000 is smaller than at 100.

When you are done, send your work to your teacher in the terminal.
